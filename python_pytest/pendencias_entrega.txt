2.4 README

Arquivo: README.md da pasta python_pytest. O atual é o original do kata, em inglês, com só a
descrição do exercício e três linhas de instalação. Precisa ser reescrito.

Onde o enunciado pede:
- Passo 12: "Finalizem documentação, README, evidências, código e uma apresentação breve".
- Item 5.9: "Criar README com dependências, ambiente, execução, testes, análises de segurança,
  estrutura de pastas e decisões arquiteturais."
- Barema: critério "README e organização", 0,5 ponto, observação "Execução independente". Ou
  seja, alguém de fora precisa conseguir rodar o projeto só lendo o README.

O que o README precisa ter:
a) Dependências: o requirements.txt (pytest, approvaltests, pytest-approvaltests e coverage),
   igual ao original, e o Python usado (3.11.5).
b) Ambiente: Windows 10, ambiente virtual (venv), terminal cmd. Avisar que o PowerShell grava
   arquivos de saída em outra codificação.
c) Execução: criar a venv, ativar, instalar as dependências, rodar os testes.
d) Testes: pytest -v, a cobertura (coverage run --source=src -m pytest e coverage report -m) e
   o que cada arquivo de teste verifica.
e) Análises de segurança: o ambiente separado das ferramentas, as versões (Bandit 1.9.4,
   pip-audit 2.10.1, Safety 3.8.1), os comandos e onde estão as evidências e o relatório.
f) Estrutura de pastas: src, tests, docs, docs/evidencias/antes e docs/evidencias/depois.
   Explicar que a pasta docs fica dentro de python_pytest, e não na raiz como na estrutura
   sugerida, porque o repositório-base tem várias linguagens; o enunciado diz que a estrutura é
   ilustrativa e pede para preservar os arquivos do repositório-base.
g) Decisões arquiteturais: Strategy, Template Method, fábrica simples, calculadoras separadas
   do carrinho, combos em classe própria, interfaces públicas mantidas e os itens mantidos por
   decisão da equipe (plano de contingência, seção 3.1).
h) Lista dos documentos de docs/, com uma linha sobre cada um.
